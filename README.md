
## Estrutura do projeto

Este repositório organiza os artefatos de análise e especificação de requisitos em pastas separadas para facilitar a compreensão e a manutenção do projeto. 

### Estrutura de arquivos e pastas

- README.md — documento inicial com o contexto e a organização do projeto.
- analise/ — pasta com os artefatos da fase de análise.
  - duvidas-e-lacunas.md — registro das dúvidas e lacunas identificadas.
  - regras-de-negocio.md — descrição das regras de negócio.
  - requisitos-funcionais.md — lista dos requisitos funcionais.
  - requisitos-nao-funcionais.md — lista dos requisitos não funcionais.
- especificacao/ — pasta com os artefatos da fase de especificação.
  - resultado-analise.md — resumo consolidado dos resultados da análise.
  
## Escopo da atividade

Utilizando a GenAI como apoio, foram realizadas a atividade de identificação sobre quais artefatos de especificação seriam mais adequados para representar os requisitos do projeto.

+ qual ferramenta de GenAI foi utilizada
```text
GitHub Copilot
```  

+ como IA apoiou as diferentes etapas da atividade
```text
A IA auxiliou na identificação e organização dos requisitos funcionais, não funcionais, regras de negócio e lacunas a partir das histórias de usuário da etapa de elicitação. Também ajudou a informar e estruturar os artefatos recomendados para esta etapa do projeto.

no arquivo denominado resultado-analise.md, estão registradas as conclusões da análise.
```

+ quais sugestões foram aceitas
```text
- foram aceitos os artefatos histórias de usuário refinadas com critérios de aceitação, o diagramas de fluxo de processo (BPMN), o Protótipo de interface e a Matriz de rastreabilidade.
```

+ quais sugestões foram descartadas ou modificadas e as justificativas
```text
- As sugestões de Casos de uso e Diagrama UML de caso de uso e/ou de classes foram descartadas, uma vez que vejo como redundantes a histórias de usuário.
```

+ por que os artefatos escolhidos foram considerados os mais adequados para esse projeto.
```text
Os artefatos escolhidos informam de maneiras diferentes - textual, gráfico e interativa (protótipo) - as necessidades e expectativas dos stakeholders.
```
